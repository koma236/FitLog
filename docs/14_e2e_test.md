# 16. E2Eテスト（Playwright）

> 壁打ち用の草案。未承認・未実装・独立レビュー未実施。数値・方式は提案であり、実行結果ではない。

### 16.1 位置づけ
UIからAPI・DB・画像までつながる主要操作を確認する。UIモックの操作成功をアプリE2Eの成功にしない。

### 16.2 ツール・環境
Playwright＋TypeScript、独立したテストDBとS3互換ストレージ。ポート・起動停止・実コマンドは基盤整備で確定。並列テストは利用者・オブジェクトキーを分離し、既存データを消さない。

### 16.3 シナリオと対応
UC-01〜13を2人のブラウザコンテキストで実行。登録→ログイン→記録作成→画像→検索→フォロー→フォロー中一覧→いいね→コメント→本人編集→リロード→ログアウト。第三者の更新・削除拒否はAPI結合テストでも確認する。

### 16.4 シナリオでは足りない観点
空一覧、切断・再試行、二重送信、セッション失効、CSRF不正、投稿削除とコメント送信の競合、容量上限・画像偽装、カーソル境界。

### 16.5 アクセシビリティ・ブラウザ性能
主要画面でaxe serious/criticalなし。キーボードだけで記録作成・送信できること。性能値は端末・ネットワーク・ウォーム状態を併記して測定する。

### 16.6 AWS上の撮影台本
1. デモ環境URLを開き、Aとしてログインする。
2. 日付・種目・セット・メモ・写真を入力して記録する。
3. BとしてAを検索・フォローし、フォロー中一覧から記録を開く。
4. いいね・コメントを付け、A側でも件数と内容を確認する。
5. 本人編集、プロフィール画像変更、リロード後の永続性、ログアウトを確認する。
6. 動画をローカルへ保存・再生確認後、破棄手順へ進む。

### 16.7 結果の記録
動画・スクリーンショット・テスト結果は実行した環境とcommitに紐づける。Cookie、メール、AWSアカウントIDや秘密を撮影しない。実施前の台本を成功証跡と表現しない。現時点は未実施。
