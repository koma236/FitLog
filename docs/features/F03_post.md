# 機能定義書 F03: 筋トレ記録・画像投稿

> 壁打ち用の草案。未承認・未実装・独立レビュー未実施。数値・方式は提案であり、実行結果ではない。

## 1. 概要 / 目的
筋トレ記録・画像投稿を通じて筋トレ記録と交流を提供する。MyTimelineの同IDの責務を引き継ぎ、記録データ・Python基盤に合わせる。
## 2. 機能詳細
実施日・1〜10種目・各1〜20セットを保存。投稿＝筋トレ記録。メモ・写真は任意。本人のみ編集削除。画像は初版1枚案。
## 3. 対象画面
SCR-03, SCR-04, SCR-08
## 4. API エンドポイント案
| メソッド | パス |
|---|---|
| POST | `/api/posts` |
| GET | `/api/posts/{id}` |
| PUT | `/api/posts/{id}` |
| DELETE | `/api/posts/{id}` |
| PUT | `/api/posts/{id}/image` |
| DELETE | `/api/posts/{id}/image` |
共通エラーは `{"code":"...","message":"...","fieldErrors":{},"requestId":"..."}` 案。[エラー一覧と共通契約](../api/README.md)に定義する。Cookie/CSRFを使う。
## 5. データ
posts、workout_exercises、workout_sets、post_images。[ER図](../07_er_diagram.md)参照。
## 6. バリデーション / 制約
種目名1〜80、重量0〜999.99kg（小数2桁）、回数1〜999、メモ500文字。画像JPEG/PNG・5MiB以下・decode後最大2000万画素案。実形式をdecodeで確認し再エンコード、EXIFを除去。本人の投稿へサーバー生成キーで保存。
## 7. エラーハンドリング / 異常系
不正入力400、権限403、不在404、競合409、容量413、画像不正415、S3失敗503。画像更新は新規保存→DB切替→旧画像削除。失敗した旧画像削除は再試行対象として追跡し、DB切替前の失敗で旧画像を失わない。投稿と画像は別操作で、画像失敗時は記録保存済みと表示して再試行可能にする。
request/response・HTTP状態・エラーコードは[OpenAPI](../api/openapi.json)に定義したレビュー前の契約案。[受け入れ条件](../acceptance.md)を検証の根拠にする。
