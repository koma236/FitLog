# 4. ユースケース

> 壁打ち用の草案。未承認・未実装・独立レビュー未実施。数値・方式は提案であり、実行結果ではない。

### 4.1 アクター
ゲストは登録・ログインのみ。ログイン利用者は記録閲覧と交流ができる。環境運用者はデモを構築し、撮影・破棄・再構築する。

### 4.2 ユースケース一覧
| ID | 操作 | 基本フロー | 失敗時・結果 |
|---|---|---|---|
| UC-01 | 登録 | username・表示名・メール・パスワード→登録→タイムライン | 重複・不正値を拒否し、ユーザーを増やさない |
| UC-02 | ログイン | メールとパスワード→ログイン | 失敗時は存在の有無を区別しないメッセージ |
| UC-03 | ログアウト | ログアウト→ログイン画面 | 旧セッションによる再操作を拒否 |
| UC-04 | タイムライン | フォロー中／すべてを切替→追加読込み | 0件、読込み中、再試行を区別 |
| UC-05 | 記録作成 | 実施日→種目→セット→メモ・画像→保存 | 不正セットは全体を保存しない |
| UC-06 | 記録編集・削除 | 本人の記録→編集保存／削除確認 | 他人のIDでAPI操作しても拒否 |
| UC-07 | コメント | 詳細→コメント入力→送信 | 空欄・上限超過で保存しない |
| UC-08 | コメント編集・削除 | 自分のコメント→更新／削除 | 件数と一覧に反映 |
| UC-09 | いいね | 押す→件数増加→解除 | 再送でも重複しない |
| UC-10 | フォロー | 他人のプロフィール→フォロー／解除 | 自己フォローを拒否 |
| UC-11 | ユーザー検索 | username・表示名の部分一致 | 0件と空検索を区別 |
| UC-12 | プロフィール | 名前リンク→情報と記録一覧 | メールは公開しない |
| UC-13 | プロフィール編集 | 本人が表示名・自己紹介・画像を変更 | 失敗時に既存の画像を失わない |
| UC-14 | デモ環境往復 | apply→配置→migrate→seed→撮影→destroy→再apply | 残存リソースと失敗の復旧方法を記録 |

### 4.3 学習用の代表シナリオ
利用者Aがベンチプレスの記録と写真を投稿する。利用者BがAを検索・フォローし、フォロー中タイムラインから記録を開いていいねとコメントを付ける。Aがコメントを確認し、記録を編集する。リロード後も結果を確認し、BによるAの記録編集が拒否されることも検証する。
