# 6. 非機能要件

> 壁打ち用の草案。未承認・未実装・独立レビュー未実施。数値・方式は提案であり、実行結果ではない。

| 項目 | 草案の基準 |
|---|---|
| 構成 | TypeScript SPA＋REST API＋PostgreSQL＋S3 |
| 操作環境 | Chromeの検証時点の版。デスクトップ主対象、幅375pxでも主要操作の横はみ出しを避ける |
| アクセシビリティ | ラベル、キーボード、フォーカス、エラーの関連付け。主要画面でaxeのserious/criticalが0 |
| 性能 | 同時利用5名・記録1,000件の固定シードでAPI p95 1秒未満を目標。画像転送・初回起動は別計測 |
| 権限 | ゲストは投稿等を取得できない。更新・削除は本人。全記録を会員間で共有することは確定 |
| 通信 | 公開環境はHTTPS。認証CookieはSecure・HttpOnly・SameSite=Lax、更新はCSRF検証 |
| キャッシュ | 認証済みAPIを共有キャッシュしない。CookieとCSRF情報をCDNで混同しない |
| パスワード | Djangoの標準ハッシュ・検証器を使用。独自暗号・平文保存を禁止 |
| 入力 | サーバーが最終判断。文字数はUnicodeコードポイント、正規化方針をAPIに明記 |
| 秘密 | 環境変数・state・秘密鍵・認証CookieをGitやログに保存しない |
| 永続性 | アプリ再起動・リロードでデータ維持。destroyではデモデータを削除する設計 |
| 可用性 | 単一環境のデモ。SLA・Multi-AZ・常時稼働は要求しない |
| 品質 | ローカルで静的解析・単体・DB結合・必要なE2Eを実行。未実行を成功にしない |
| 再現性 | 依存lock、Dockerイメージ固定、マイグレーションとデモseed、構築・破棄の記録 |

性能値は設計上の仮基準であり測定結果ではない。コスト削減と性能が両立しない場合は結果を示して構成・基準を再検討する。
